# 截图文档编写

## 目标与边界

本 Skill 负责将已经确认的角色、真实导航结构、页面状态和截图组织成 Markdown 文档，决定：

```text
文档拆分为哪些文件
→ 每份文件面向哪些角色
→ 标题按什么层级排列
→ 导航模块按什么顺序写
→ 每张图前后写什么必要正文
→ 哪些内容不应写入正文
```

本 Skill 不负责：

- 决定一个模块需要哪些截图、截图状态、裁剪范围或标注意图；
- 操作浏览器、登录系统、采集图片或计算标注坐标；
- 修改业务代码、页面、配置、数据库结构或初始化数据；
- 导出 DOCX。

截图规划由 `screenshot-document-authoring` Skill 负责，真实页面采集与标注由 `real-web-screenshot` Skill 负责。正文只能引用已经实际生成并通过检查的图片；不得把计划中的图片、未到达的页面状态或未实际执行的操作写成既有事实。

## 何时加载

在下列任务开始前加载本 Skill：

- 新建、补写、重组或评审截图文档的 Markdown；
- 调整章节顺序、标题层级、角色归属、图片标题或图片前后的正文；
- 将已完成的截图计划和图片装配到 Markdown。

只规划或采集图片时，不加载本 Skill；只导出已确认的 Markdown 时，也不改写正文。

## 两份默认文档

截图文档默认拆为两份 Markdown。用户明确指定其它文件名或只要求其中一份时，按用户范围处理，不自动创建另一份。

```text
学生实验指导书.md
└─ 仅学生角色的操作说明

系统说明书.md
├─ 教师操作说明
└─ 管理员操作说明
```

“系统说明书”在本任务中只指教师和管理员如何完成实际操作，不写成技术架构、接口、数据库、部署、源码或泛化产品介绍。

## 真实导航决定章节顺序

章节顺序以目标角色在真实浏览器中实际可见、实际可点击的主导航入口为准：

```text
登录目标角色
→ 读取导航栏从上到下或从左到右的显示顺序
→ 按同一顺序编写模块标题、模块总览图和后续操作说明
```

不得按源码路由、组件目录、字母顺序、页面发现顺序、截图生成顺序或主观重要程度重排。

以下内容不能提升为导航模块标题：

- 页面页签；
- 按钮；
- 弹窗；
- 表格行操作；
- 面包屑；
- 卡片内快捷入口；
- 源码路由或组件名称。

导航入口不存在、不可点击、跳转异常或当前角色无权访问时，不把该页面编入可用操作说明；保留已确认内容并报告实际问题。

## 标题层级

### 学生实验指导书

学生文档只覆盖学生角色，文档标题之后直接以学生真实导航模块作为二级标题：

```markdown
# 学生实验指导书

## 我的课程

模块用途和入口说明。

![我的课程总览](./assets/学生/我的课程/01-我的课程总览-标注.png)

### 查看课程内容

必要的操作说明和对应图片。

## 学习任务
```

不得再增加一个只写“学生”的空角色标题，也不得将非导航对象列为同级二级标题。

### 系统说明书

系统说明书以角色分组，教师和管理员分别使用二级标题；每个角色下的真实导航模块使用三级标题，并严格按该角色导航栏顺序排列：

```markdown
# 系统说明书

## 教师操作

### 班级管理

模块用途和入口说明。

![班级管理总览](./assets/教师/班级管理/01-班级管理总览-标注.png)

#### 查看班级

必要的操作说明和对应图片。

## 管理员操作

### 用户管理
```

角色分组标题不是导航模块；教师和管理员各自的模块顺序只由各自真实导航栏决定。不同角色即使有同名模块，也必须在各自章节中独立说明，不混用入口、截图或权限描述。

## 模块正文与图片装配

每个导航模块按以下顺序编写：

```text
模块标题
→ 简短说明该模块用于完成什么业务操作
→ 模块总览图及其必要说明
→ 仅在确有独立说明价值时继续写操作、状态或结果小节和内容图
```

模块总览图、内容图的数量、状态与标注意图以 `screenshot-document-authoring` Skill 的计划为准。后续内容图必须有不同于总览图的独立说明价值；不得仅因裁掉导航栏而重复同一页面内容。

图片前后的正文只说明读者完成当前操作所需的入口、动作、可见结果或状态。标注文字用于定位，不把整段说明塞进图片。普通字段必填规则、格式限制和表单校验提示默认不写入正文，也不为此补充截图。

## 正文边界

正文使用真实页面和业务中的名称，保持简短、直接、可操作：

- 页面上叫“开始考试”时，正文写“开始考试”；
- 只描述已经在真实页面中确认的角色、入口、操作和结果；
- 说明必要的权限条件、不可逆操作或业务前置条件；
- 不把截图过程中发现的页面缺陷、入口不可达、权限异常或推测的补救措施写进正式文档；这些问题单独报告用户。

不得写入：

- 源码、路由、接口、数据库、组件、测试数据或其它内部实现；
- 操作无关的背景介绍、流程教程、验收备注或责任规避文案；
- 未实际截图或未实际执行的页面状态；
- 为凑章节而创建的空标题。

## 图片路径

图片放在目标 Markdown 同级的 `assets/` 下，按角色和真实导航模块分目录，例如：

```text
学生实验指导书.md
系统说明书.md
assets/
├─ 学生/
│  └─ 我的课程/
├─ 教师/
│  └─ 班级管理/
└─ 管理员/
   └─ 用户管理/
```

Markdown 只使用相对路径引用实际存在的图片。文件名、图片标题和章节名称使用真实业务词，不使用内部名称。

## 完成前检查

```text
[ ] 当前任务只创建或修改用户要求的文档文件
[ ] 学生实验指导书只包含学生角色
[ ] 系统说明书只包含教师和管理员操作说明
[ ] 每个角色下的导航模块标题顺序与真实导航栏一致
[ ] 页签、按钮、弹窗、卡片入口和源码路由没有被误写为导航模块标题
[ ] 教师和管理员的入口、图片和权限描述没有混用
[ ] 每张图片引用存在且相对路径可解析
[ ] 每张图片前后的正文只说明当前操作所需内容
[ ] 普通表单校验提示没有被写入正文或作为独立截图
[ ] 正文没有内部实现、页面缺陷、无意义免责声明或空章节
[ ] Markdown 标题层级连续
```
