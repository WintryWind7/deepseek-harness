# 截图文档编写：截图规划

> 当前版本只规定文档需要什么截图。Markdown 正文写法、排版和 DOCX 导出将在后续补充。

## 目标与边界

本 Skill 负责从文档角度决定：

```text
文档面向哪些角色
→ 每个角色有哪些导航大模块
→ 每个导航大模块需要哪些页面状态
→ 哪张图是模块总览图
→ 哪些图只截主内容区域
→ 每张图要说明什么、框什么、写什么标注文字
→ 图片怎样编号和存放
→ 将逐图要求交给 real-web-screenshot Skill 执行
```

本 Skill 不负责：

- 操作 Playwright；
- 登录真实系统；
- 等待页面加载；
- 计算截图坐标；
- 使用 Pillow 绘图；
- 计算文字边界和箭头起终点；
- 判断某个按钮是否会写入业务数据；
- 实际读取和检查图片像素。

这些实现工作由 `real-web-screenshot` Skill 负责。

## 与截图 Skill 的协作关系

本 Skill 和 `real-web-screenshot` 是两项可以独立使用的能力：

- 用户只讨论文档需要哪些截图时，只加载本 Skill，不执行真实截图；
- 用户已经明确指定某张脱离文档结构的独立图片，只要求采集或修正时，可以只加载 `real-web-screenshot`；
- 用户要求规划并完成一组截图时，先由本 Skill 形成截图计划，再按用户确认的范围把相关单图规格交给 `real-web-screenshot`；
- 用户可以分多轮逐步规划、截图、修正和写入文档，不要求一次完成全部步骤。

本 Skill 输出截图计划时，截图 Skill 不得自行改变文档的角色、导航模块、图片顺序和截图类型。真实页面无法达到计划状态时，截图 Skill 返回具体限制，由文档 Agent 在后续对话中调整计划或向用户确认，不自动继续完成其它未请求工作。

## 文档截图任务识别

只要截图用途属于以下任一情况，即使用户当前只说“截一下我看看”或只要求交付图片，也必须将其识别为文档截图任务并应用本 Skill：

- Markdown 图文文档；
- 产品说明书或操作手册；
- 培训材料；
- 测试或验收报告；
- 需求说明或演示材料；
- 按角色、导航或模块整理的一组截图；
- 用户把页面或功能清单称为“文档要求”。

文档截图任务不能因为当前不要求编写 Markdown，就跳过本 Skill。可以只完成截图并停止，但必须先按照文档结构判断模块总览图、模块内容图、保留区域和标注意图。

## 文档按角色和导航组织

截图文档按以下层级组织：

```text
角色
└─ 导航大模块
   ├─ 第一张：模块总览图
   └─ 后续：模块内容图
```

### 角色

角色是系统中真实存在、具有独立页面入口或数据范围的用户身份，例如：

```text
教师
学生
管理员
```

不同角色即使存在名称相似的功能，也分别在各自角色章节中说明。不得使用教师导航截图说明学生入口，也不得把管理员拥有的入口写成普通用户入口。

### 导航大模块

“导航”只指真实页面中的主要导航栏入口。导航栏可以位于：

- 左侧；
- 顶部；
- 其它固定的主要导航区域。

以下通常不属于导航大模块：

- 页面页签；
- 按钮；
- 弹窗；
- 表格行操作；
- 面包屑；
- 页面内部快捷入口。

文档以目标角色真实可见的导航栏入口划分大模块，例如：

```text
教师
├─ 班级管理
├─ 课程管理
└─ 考试管理

学生
├─ 我的课程
├─ 学习任务
└─ 我的考试
```

不按源码组件、接口、数据库对象或路由文件划分文档大模块。

## 每个导航大模块的截图结构

同一份文档中，每个“角色 + 导航大模块”必须恰好规划一张模块总览图：不能缺少，也不能重复。只有模块内部确实需要说明的状态，才继续规划模块内容图。

```text
01 模块总览图
02 模块内容图
03 模块内容图
...
```

不得一进入新导航模块就直接放内部按钮、弹窗或结果图，而缺少模块总览图；也不得在同一模块的后续小节重复生成第二张导航入口总览图。

规划已有文档的新增或补拍截图时，先检查该角色导航模块是否已经存在总览图：

- 已存在且页面未变化：不得重复规划；
- 不存在：先补一张总览图，再规划内部内容图；
- 已存在但导航或主页面范围发生变化：将原总览图列为替换，不新增第二张。

## 模块总览图

### 用途

模块总览图用于回答：

```text
当前是什么角色
从导航栏哪里进入
进入后主页面是哪一块
```

### 必须包含的区域

模块总览图必须同时包含：

- 当前角色真实可见的导航栏；
- 已经展开、选中或高亮的目标导航项；
- 该导航对应的主页面主要内容区。

无论导航栏位于左侧还是顶部，导航入口和主页面范围必须在同一张图中清楚可见。

### 必须规划的标注

每张模块总览图至少规划两项标注：

```text
真实导航名称 + 入口 ───► 目标导航项
真实模块名称          ───► 主页面中实际可见的主要内容
```

例如目标菜单叫“班级管理”时，导航标注文案写“班级管理入口”，而不是泛称“导航栏入口”。

导航目标说明：

- 目标框只覆盖进入该模块时真正需要点击的导航项可点击区域；
- 通常包含该菜单项的图标、名称和实际点击背景，但不扩大到上级菜单组、整个导航栏或相邻菜单；
- 如果进入模块前需要展开上级菜单，先完成展开操作；最终导航目标框仍只框实际进入模块的目标菜单项，除非文档明确需要说明展开动作；
- 导航栏可滚动时，必须先滚动导航容器，使目标菜单项完整可见、没有被裁切并且真实可点击，再截模块总览图；
- 不得因为目标当前位于导航栏可视区之外，就改用整个导航栏的大框或只框一部分露出的菜单项。

主页面目标说明：

- 目标框覆盖该状态下实际可见、能够说明模块的主要内容，例如卡片组、表格及其已加载行、结果区域、表单区或明确的空状态；
- 不得只框页面标题；
- 不得只框表头；
- 不得用一个很小的局部区域冒充整个主页面范围；
- 不得因为某个布局父容器很大，就框住其中大部分为空白的区域；目标框应紧贴实际有意义的内容范围，截图本身仍保留完整主内容区上下文；
- 标注文案写图中实际可见的业务对象或状态。“班级列表”只能指向已显示的班级卡片、表格行或列表区域；没有可见列表内容时，先达到有数据的真实状态，或如实标注“暂无班级”等实际空状态，不得把空白容器称为列表。

### 标注文字

导航入口的标注文字使用真实导航名称加“入口”，例如：

```text
班级管理入口
课程资源入口
考试管理入口
```

主页面标注文字使用导航大模块或实际可见内容在界面中的真实名称，例如：

```text
课程资源
班级管理
考试管理
```

用户有明确文案要求时按用户要求，但不得使用源码内部名称和临时技术名称。

导航入口的文字必须使用对应菜单的真实名称加“入口”，放在目标导航项附近，并使用一条自然角度的单段直达直线箭头连接，不能使用折线或多次转弯。文字绝不能覆盖本图任何目标框及其框内的菜单图标、名称或点击区域；目标框外的普通页面内容没有同等保护优先级，如果为了避让它们会使文字离目标过远，应保持文字靠近导航入口并允许覆盖这些普通页面内容。以 `1920 × 900` 为基准，文字边缘到目标框边缘的箭头线段不得短于 48 像素；48 像素只是下限，满足全部避让要求后仍应选择最短自然的位置。无法兼顾时拆分标注，不得把文字贴框、拉得过远或把箭头改成折线。

模块总览图的这两项标注是强制要求，不能只框不写文字、只写文字不画箭头，也不能只标导航或只标主页面。执行规格必须把两项标注分别列出，截图完成后逐项验收。

## 文档截图默认需要标注

文档截图默认交付标注图，同时保留对应原始图。除非用户明确说“只要原始截图”或“不要标注”，不得把未标注原图当作最终文档截图交付。

- 模块总览图：必须标注真实导航名称入口和主页面实际有效内容；
- 模块内容图：必须根据该图的文档目的标注关键按钮、页签、表单区域、表格、详情或结果区域；
- 如果某张图没有任何值得标注的目标，应重新判断这张图是否有必要进入文档，而不是默认输出一张无标注页面；
- 原始图用于复核和后续重新标注，文档默认引用标注图。

## 模块内容图

### 用途

模块内容图用于说明导航大模块内部的：

- 页签；
- 按钮；
- 表单；
- 弹窗；
- 筛选条件；
- 表格；
- 详情；
- 操作状态；
- 结果状态。

### 截图范围

所有模块截图都以同一个 `1920 × 900` 完整页面视口为基础。模块总览图直接使用完整视口；同一导航大模块后续的内容图，必须从对应的 `1920 × 900` 完整视口截图中按导航栏与主内容区的真实布局边界切出主内容区，不再包含主要导航栏。

- 左侧导航布局：完整视口被切分为左侧导航区和右侧主内容区，两块宽度之和必须等于 1920，高度均保持 900；内容图使用右侧主内容区；
- 顶部导航布局：完整视口被切分为顶部导航区和下方主内容区，两块高度之和必须等于 900，宽度均保持 1920；内容图使用下方主内容区；
- 其它布局：导航区与主内容区必须共同无缝组成原始 `1920 × 900` 视口，不重叠、不留缝。

切分只能裁剪，不能拉伸、压缩、缩放或重新排版。切分后的主内容图保持原截图像素比例和原始页面尺寸关系。

“主内容区”是导航栏之外的完整页面内容面板，不是当前标注目标的包围框。无论要标注的是一个按钮、页签、表格、弹窗还是局部结果区域，截图都必须保留完整主内容区，再在这张内容大图中绘制目标框。绝对禁止只截目标框区域或把目标 DOM 元素单独截图作为模块内容图。

裁剪后的完整主内容区应保留该页面原本可见的标题、页签、工具栏、弹窗、表格、表单、留白和结果区域，即使其中只有一小部分需要标注。

### 不重复导航标注

模块内容图不再：

- 展示主要导航栏；
- 框选同一个导航入口；
- 重复标注目标导航项；
- 为说明当前位置重新拼入导航截图。

如果文档进入另一个导航大模块，应结束当前模块，先为新模块规划一张新的模块总览图。

### 稳定裁剪边界

同一页面布局中的内容图必须复用一致的导航与内容切分边界，使内容图尺寸和版式稳定。切分边界只在页面布局本身发生变化时调整，不能根据每张图的标注目标大小变化。

记录切分边界时应满足尺寸守恒。例如左侧导航宽度为 `nav_width`：

```text
导航区：(0, 0, nav_width, 900)
内容区：(nav_width, 0, 1920, 900)
导航区宽度 + 内容区宽度 = 1920
```

顶部导航高度为 `nav_height`：

```text
导航区：(0, 0, 1920, nav_height)
内容区：(0, nav_height, 1920, 900)
导航区高度 + 内容区高度 = 900
```

切分后的内容图不得再缩放到 `1920 × 900`，也不得为了统一输出尺寸而拉伸；它的像素尺寸就是完整视口减去导航区域后的自然尺寸。

采用导航与内容分离的原因是：

- 导航栏可能增加、减少、重命名或调整顺序；
- 导航变化后，只需优先重做各模块的第一张总览图；
- 模块内部页面没有变化时，后续内容图不因导航变化而全量重截。

## 需要截哪些模块内容图

截图数量由文档目标决定，不按页面中所有按钮机械穷举。

优先规划能够说明以下信息的页面状态：

```text
读者从哪里开始
关键操作在哪里
需要填写或选择什么
完成前需要核对什么
完成后会看到什么结果
```

### 操作说明

按必要状态规划：

```text
模块总览图
→ 关键操作状态
→ 必要配置状态
→ 结果状态
```

用户只需要查看某个页面结果时，不强行补齐所有中间操作图；但进入一个新的导航大模块时，仍必须先有该模块的总览图。

### 功能介绍

优先规划：

```text
模块总览图
→ 主要页面区域
→ 重要详情或结果
```

不把每个按钮都截成单独图片。

### 测试或验收报告

优先规划能够证明实际结果的状态：

```text
模块总览图
→ 测试前置状态
→ 实际结果状态
→ 必要的异常或边界状态
```

不能用预期说明代替真实结果截图。

## 功能覆盖清单

规划一个页面、详情页或长页面的截图前，先盘点本次文档范围内的独立功能区和用户操作：页面区块、列表或表格、关键入口、筛选、填写、弹窗、确认、结果和状态变化。页面需要滚动时，盘点首屏之外的实际功能区，不能只把首屏当作整页。

对每项功能逐一写明一种覆盖方式：

- 当前已计划图片中的明确标注；
- 另一张已计划图片中的明确标注；
- 仅由正文说明；
- 不属于当前文档范围，并写明原因。

仅仅出现在图片背景、同屏未标注，或位于当前红框之外，不算已被说明。一个图的主题是“班级工作概况”时，下方“班级成员”仍是独立功能区；必须在覆盖清单中决定后续图片、正文说明或明确排除，不能静默遗漏。

### 何时只由正文说明

“仅由正文说明”只适用于同时满足以下条件的内容：

1. 不需要读者寻找新的入口、点击、填写、选择、确认或查看新的结果状态；
2. 相关页面对象已经在另一张已标注图片中清楚出现，或其位置对读者并不重要；
3. 正文只补充业务含义、权限条件、前置条件、数据口径或与其它功能的关系，截图不会新增可理解的操作或状态证据。

例如，可以用正文解释工作概况中的数量含义、角色权限或操作前置条件。不得只用正文带过独立列表、表格、筛选、分页、按钮入口、填写界面、弹窗、确认、操作结果或状态变化。若某个入口和点击后的结果都由同一张已标注图直接说明，可以共用该图；打开弹窗、填写、选择、确认或产生不同结果时，必须另有对应状态图。

## 一张图表达一个主题

每张图应有一个清晰主题，例如：

```text
课程资源总览
新建考试入口
考试规则配置
考试结果
```

如果一张图需要大量红框和标注才能解释，应优先：

1. 拆成两个页面状态；
2. 减少非必要标注；
3. 把详细解释放入 Markdown 正文。

不得通过缩小字体、使用很长箭头或堆叠大量标注来容纳过多内容。

## 标注意图

本 Skill 只决定标注“说明什么”和“目标是什么”，不决定具体坐标。

每项标注意图至少包含：

```text
目标名称
目标类型：导航项、按钮、页签、表单区、表格、结果区等
标注文字
是否需要序号
为什么需要标注
```

### 区域说明

说明页面区域时使用简短名称：

```text
课程资源入口
课程资源
考试列表
筛选条件
结果区域
```

### 操作说明

说明操作时使用“动词 + 对象”：

```text
点击新建考试
选择考试试卷
查看考试结果
```

### 序号

序号默认不添加。

只有同一张图需要表达连续步骤，或用户明确要求编号时，才在计划中指定 ①、②、③。是否实际能够清楚放置，由截图 Skill 在布局检查时验证。

## 截图计划

批量截图前必须形成截图计划。截图计划不记录“每张图从哪个路由或导航进入”；导航归属由角色和导航大模块层级表达，路由只是截图执行阶段的内部实现信息。

每张图至少记录：

| 字段 | 含义 |
|---|---|
| 编号 | 模块内稳定序号 |
| 文档位置 | 角色、导航大模块和小节 |
| 角色 | 使用哪个真实角色 |
| 导航大模块 | 图片归属哪个导航栏入口 |
| 截图类型 | 模块总览图或模块内容图 |
| 目标状态 | 图片需要表达的真实页面状态 |
| 保留区域 | 完整导航与主页面，或不含导航的主内容区域 |
| 标注意图 | 需要框选的目标和标注文字；文档截图默认不得为空 |
| 标注要求 | 默认必须生成标注图，只有用户明确要求时才允许仅原图 |
| 序号 | 是否需要 ①、②、③ |
| 写操作 | 是否预计需要产生或修改业务数据 |
| 文件名 | 计划输出名称 |

示例：

```markdown
| 编号 | 文档位置 | 角色 | 导航大模块 | 类型 | 目标状态 | 标注意图 |
|---|---|---|---|---|---|---|
| 01 | 教师 / 课程资源 | 教师 | 课程资源 | 总览图 | 列表加载完成，导航高亮 | 课程资源入口、课程资源 |
| 02 | 教师 / 课程资源 / 查看资源 | 教师 | 课程资源 | 内容图 | 资源详情已打开 | 资源内容 |
```

## 图片编号和目录

图片按角色和导航大模块存放：

```text
assets/
├─ 教师/
│  ├─ 班级管理/
│  ├─ 课程管理/
│  └─ 考试管理/
└─ 学生/
   ├─ 我的课程/
   ├─ 学习任务/
   └─ 我的考试/
```

每个导航大模块独立编号，第一张固定是总览图：

```text
01-考试管理总览.png
01-考试管理总览-标注.png
02-考试列表.png
02-考试列表-标注.png
03-新建考试弹窗.png
03-新建考试弹窗-标注.png
```

文件名使用页面和文档中的真实业务词，不使用组件名、路由名、随机哈希和临时编号。

规划过程中的中间文件、浏览器脚本、认证缓存和预览文件放到当前工作区的 `.dsh/qa-tmp/screenshot-document/`，不放仓库根目录的 `qa-tmp/`，不写入正式文档目录，也不提交 Git。最终交付仍只使用本节的 `assets/` 结构。

## 交给截图 Skill 的执行规格

每张计划图片交给 `real-web-screenshot` 时，至少提供：

```text
图片编号和输出路径
目标角色和认证上下文
需要达到的真实页面状态
保留区域：完整 1920 × 900 视口，或从该视口切出的完整主内容区边界
需要框选的目标及其语义描述
标注文字
必须生成标注图：是或否
是否需要序号
是否允许业务写操作
```

截图 Skill 返回：

```text
原始截图
标注截图
实际页面状态
是否执行写操作
逐图检查结果
无法满足的计划要求
```

文档 Agent 只能把已经通过逐图检查的图片写入正式 Markdown。

## 完成前检查

```text
[ ] 文档按角色和真实导航栏入口组织
[ ] 每个“角色 + 导航大模块”恰好有一张模块总览图，没有缺少或重复
[ ] 模块总览图是该模块第一张图
[ ] 总览图强制要求分别标注真实导航名称入口和主页面实际有效内容
[ ] 标注文案使用图中实际可见的业务名称、对象或状态，没有使用脱离对象的通用结构名称
[ ] 目标框框住实际可见的对应内容，没有把空白布局容器称为列表、表格或结果区域
[ ] 同一模块后续图片要求从 1920 × 900 完整视口切出完整主内容区域，不包含或标注导航栏
[ ] 导航区与内容区切分后尺寸之和仍等于原始固定视口
[ ] 没有把标注目标、目标框或目标 DOM 元素误当作截图范围
[ ] 内容图保持切分后的自然尺寸和原比例，没有拉伸或缩放
[ ] 文档截图默认要求生成标注图，没有把原始图直接作为最终交付
[ ] 截图计划没有逐图记录路由或进入路径
[ ] 没有把页签、按钮或面包屑误当成导航大模块
[ ] 没有混用不同角色的导航入口
[ ] 每张图片只有一个清晰主题
[ ] 没有为了穷举按钮而规划过多截图
[ ] 图片编号和目录按角色、导航大模块组织
[ ] 每张图的标注意图和保留区域已经明确
[ ] 已盘点本次范围内每个独立功能区和用户操作，并为每项记录图片、正文说明或排除决定
[ ] 同屏未标注、红框外或首屏外的独立功能区没有被误认为已说明
[ ] 仅由正文说明的内容同时满足无需新入口、操作、状态或结果图的条件
[ ] 当前任务只要求规划时，没有擅自执行真实截图
[ ] 当前任务要求执行截图时，只把用户已确认的图片规格交给 real-web-screenshot Skill
```
