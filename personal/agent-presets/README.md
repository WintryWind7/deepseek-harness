# 个人预设

四个预设以官方 `standard` 的插件清单为底稿，这里只保存差异。`adapter.mjs` 每次注册时重新读取 `@deepseek-ai/dsh-web-app` 里的 `presets/standard.patch.yml`，套上差异后再注册。官方新加的工具会自动出现，除非写进 `omit`。

| 文件 | 预设 |
|---|---|
| `presets/main-dev.yml` | 开发助手 |
| `presets/project-planner.yml` | 项目规划助手 |
| `presets/screenshot-document.yml` | 真实网页文档助手 |
| [团队开发助手](presets/team-dev.yml) | 用户只跟 Lead 说。Lead 管理独立根会话、接收每轮结果；右侧“团队”面板显示管理范围和状态。 |
| `shared.yml` | 拼进每个个人预设的公共行配置，目前是压缩阈值 |

改这些 yml 后，Host 的 HMR 会重新注册。已经打开的会话仍用旧的一代，新会话用新内容。第一次换上这个中转要重启 Host。官方底稿变了也要重启后才会进来。新增加的 yml 文件要重启一次才会被监视。

`persona` 整段替换官方人设，不保留官方的 `suffix`。`omit` 按插件行 id 删掉一行，id 在底稿里不存在就启动失败。`rows.<id>.config` 浅合并，只钉住写出来的字段；`rows.<id>.disabled` 覆盖是否启用。`insert` 在某个官方行的 `before` 或 `after` 插入额外插件。写错键、找不到行、底稿读不到，都会报错。热重载失败时保留上一份成功的注册。

Web 里「查看配置」看到的是套用之后的完整清单，不是这些差异文件。

## 团队开发助手

用户在 `team-dev` 主会话与 Lead 对话。Lead 用 `open_session` 创建独立根会话，默认 `main-dev`，自动纳入管理；用 `list_sessions` 找已有根会话，再用 `manage_session` 的 `add` 或 `remove` 纳入或移出。移出不停止、不删除会话。一个工作会话同时只由一个 Lead 管理，不接受 subagent，也不支持嵌套 Lead；左侧可见的普通 fork 可以作为根会话管理。工作会话使用独立预设，不复制 Lead 的聊天上下文，默认共享工作目录。

Lead 用 `continue_session` 发任务，用 `read_session` 主动读当前状态、待答问题、最近已提交正文和真实轮次结果。读取不发送任务、不恢复工作 Agent，不包含未提交的流式思考；指定 `turn` 和返回的 `nextOffset` 可以继续读取被截断的结果。未纳入管理的根会话仍可接收消息，但不向这个 Lead 自动回传。

受管理会话的每个真实 `turn/end` 都向 Lead 发送结束原因与本轮最后一条文字回复；没有正文时也发送结束通知。轮次结束不代表整个任务完成，多条入队消息也可能合在同一轮处理。管理从纳入时的日志位置开始，不重发此前已结束的历史；回传触发 Lead 的下一轮，因此用户不必切换会话搬运结果。工作会话的所有轮次都回传，包括用户直接进入工作会话发起的轮次。

回传先确认工作会话日志持久化，再以固定消息 id 入队 Lead、确认收据持久化，最后推进管理记录中的投递位置。失败不会推进位置；Host 重启、相关会话恢复、后续轮次结束或 Lead 再次执行 `add` 时补偿未送达的真实结束轮次。已经纳入的会话再次 `add` 不改变历史起点。恢复 Lead 使用 Lead 自己的预设和模型，不用工作会话的模型覆盖它。

右侧边栏的页面选择列表提供“团队”入口。Lead 页面显示自己的管理名单；工作会话页面显示所属 Lead 和同组工作会话。面板包含预设、运行或等待状态、最近轮次结果，标题可打开对应会话；刷新只读取状态。纳入、移出由 Lead 工具操作，面板不另外提供管理按钮。面板可见时订阅变更，隐藏或卸载后关闭订阅，不轮询工作会话。

受管理会话的 `ask_user_question` 保留用户弹窗，同时转给 Lead。Lead 用 `reply_question` 回答，先回答者生效；用户先答时，Lead 的迟到回答会显示用户答案。Host 启动后已出现、尚未回答的普通根会话问题，在纳入管理时也会转给 Lead。正在等问题答案时不要用 `continue_session` 替代。Lead 先答后，原弹窗可能仍需用户关闭，迟到点击不会改变已经送给工作会话的结果。

### 配置和生命周期

[Bundle patch](cordis.patch.yml) 同时加载预设注册器和共享的团队管理 Host。[Host](team-dev/host.mjs) 与 [Lead 工具](team-dev/sessions.mjs) 共用管理实例，[Client 面板](team-dev/client.js) 读取同一实例的状态。`personal-team-sessions.config.resultChars` 默认 `12000`，范围 `1000–100000`，限制回传消息和单段读取的字符数；`questionHistoryLimit` 默认 `64`，范围 `1–1000`，限制每个会话保留的用户答题历史。两项在插件加载时验证。

管理关系和投递位置保存在 Lead 工作目录的 `.dsh/team-dev-sessions.json`，不写入官方会话格式。启动时从已知会话的工作目录加载记录；旧版仅含 Lead 和预设的记录建立新的投递起点，不重发旧结果。在途问答和状态订阅只存在于当前进程，重启后不会恢复旧弹窗；工作会话继续运行后产生的新问题仍按管理关系转发。插件卸载会取消读取、排空投递任务、释放问答等待者并关闭面板连接，不删除根会话或管理记录。

新增或替换 Host/Client 模块需要重启 DSH，并刷新当前 GUI；已经打开的会话继续保留原预设代次，Lead 工具变更应在新建团队开发助手会话中验证。客户端提供已经可加载的浏览器模块，不需要额外打包；实际生效仍以当前 Host 的 bundle 和 Client 注册结果为准。源码检查不等于已在当前页面验证。

### 限制

当前仅接入 DSH 普通根会话，不接入 Claude Code 或 Codex。多个工作会话默认操作同一工作目录，没有自动文件锁、独立 worktree 或冲突调度；Lead 负责避免重叠修改。管理记录按单个 Host 写入，不提供多个 DSH 进程共同写同一工作目录的协调。面板只显示最近结果，完整日志在原会话；会话归档或预设被改换后，回传可能被官方会话策略阻止，失败保留投递位置供恢复。
