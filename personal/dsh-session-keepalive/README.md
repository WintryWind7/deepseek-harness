# 会话保温

让最近访问过的会话在客户端保持「热」状态，切回去时立刻出标题，不再先退化成工作区名字。

侧边栏只保留当前选中会话的视图，切走时最后一个引用释放，客户端就关掉该会话的 generation；再切回来要重新走一遍 `Session.open()`（向 Host 拉取历史）。本机几毫秒无感，跨网络（如 Tailscale）要数秒，期间侧边栏标题取不到。

本插件对每个访问过的会话额外持有一份 `ctx.sessions.retain(id, { source: 'sessionKeepalive' })`。这份引用与侧边栏共享同一次 `open()`，所以侧边栏重建视图时 `reference.ready` 已经 resolve，标题瞬间出现，也不再产生新的历史请求。切走时侧边栏释放自己的引用，我们这份让 generation 继续存活。

## KEEP：保留多少个热会话

`client.js` 顶部的 `KEEP` 是保留数量，默认 `8`，按最近使用顺序淘汰（`Map` 的插入顺序即 LRU 顺序，超出的最旧一份会被 `release()`）。

**客户端内存占用随 KEEP 线性增长**：每个热会话都保留自己的完整历史，不会因为切走而释放。所以 KEEP 越大越省事，代价是常驻内存越高。

- 默认 `8`，切一个来回基本不会踩到冷启动。
- 觉得内存吃紧就降到 `4`；只有两三个会话来回切的话，`2` 到 `3` 也够用。
- 调大之前先想清楚：留着的每一个会话都是真实的历史数据。

## 边界

只解决「切换会话慢」。连接断开后列表整体重拉导致全部标题变工作区名字，是另一回事，本插件管不到。

插件不改动 DSH 任何已有代码：`index.js` 是空的 Host 半边（只为挂载这一行），逻辑全在 `client.js`，删掉目录并从 profile 里移除即可完全还原。
